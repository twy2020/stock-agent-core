# Core 控制台实施计划

**Goal:** 将 Core 控制台与模型、能力管理一起落地：概览、运行记录、接入应用、供应商账号、聚合模型、能力注册、用量费用。

## 2026-10-04 追加范围（替代下文早期限制）

用户已要求立即实施。Core 可直连配置的 VLM，也可经 OCR 工具，按调用方 visionPolicy 与模型能力双重授权；不自动双调用。供应商、账号、密钥引用分层管理，已有 model profile 兼容迁移。提供 OpenAI-compatible models/chat completions 接口，使用调用方既有凭证与模型白名单；不冒充完整 OpenAI API。

价格由管理员配置并保留币种；Core 记录网关和 Agent 的真实 usage，未知价格/用量明确缺失。供应商模型发现是预览，管理员批准后才加入可调用模型；远端价格/账单仅在确实有对应接口时获取，不猜测账单。

MCP 注册远端 Streamable HTTP 或 Core 的 HTTP/RAG 桥接。发现不等于批准；调用方同时需要 server 与 tool 授权，插件和技能按调用方批准后生效。OCR、RAG 为能力提供方；仅 SaaS/CAD 为当前 Agent 消费方。Core 桥接保持原有独立 API 可用。

管理采用列表加右侧属性栏，14px 下限，配置原子落盘和版本检查，凭证仅引用受控文件/环境变量。并行边界：providers/gateway、capabilities/MCP、management API；root 负责 UI、direct vision preparation、应用集成和验收。所有测试先用隔离配置和本地模拟服务，不用真实收费模型验证协议。

**Architecture:** 保留 Flask 与独立 Core；新增管理 API 模块及原生 HTML/CSS/JS 界面。所有管理 API 继续使用管理员鉴权；业务服务接口保持兼容。配置仅修改现有对象的名称、启停与并发等白名单字段，原子写入配置文件，无运行中任务时生效。

**Design:** 用户已批准上轮五页设计并要求开始。Apple 风格，左导航、列表工作区、右侧详情；最小字号 14px，帮助折叠，错误直接显示。不引入前端构建运行依赖、插件市场或完整注册审批平台。
